# WORK LEDGER — read me first

This is the durable, continuously-updated task list for building the framework. It is the
single source of truth. **Any agent (fresh or continuing) reads this first.** It is also a
*dogfood* of the "work ledger" mechanism the framework itself will provide (Gap C).

## How to use this ledger
- Tasks are granular and have a status: `todo | doing | done | blocked`.
- When you start a task set it `doing`; when finished set `done` and add a one-line
  evidence note (file written, decision made).
- Keep `next_action` in the frontmatter always pointing at the very next concrete step.
- Never delete completed tasks — they are the audit trail. Append new ones at the bottom
  of their section.

## The goal (verbatim intent, compressed)
Build a **spec-driven development framework** usable in Claude Code to build full-stack +
mobile apps, where **evals are a first-class, early, integrated** part of the process
(confirm code follows spec & intent, alongside not separate), that **autonomously hands off
to a fresh session before context rot**, and **preserves a granular task list** so another
agent picks up seamlessly. This is the **baseline for a self-running software factory**:
objective → spec → plan → code → evals. Build on existing GSD (v1.2.0). Write verbose
reasoning in `.md`. Use advisor + peer agents to brainstorm with variants, multiple rounds.
